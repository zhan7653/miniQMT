下面这版方案把你的系统定位为：

以 MiniQMT / xtquant 为底层接入，以本地可信数据仓库为核心，以 DataPortal 和 Broker 抽象隔离上层研究、回测、模拟盘、Agent 与真实交易接口的轻量型场内规则基金实验平台。

核心原则是：

数据先可信
回测再可信
模拟盘收益最后可信
Agent / 自动执行 / 推送全部后置

xtdata 本身适合作为行情、K 线、分笔、合约基础信息、板块分类等数据入口；它通过 MiniQMT 连接行情服务，且数据能力与 MiniQMT 当前连接环境一致，历史数据不足时通常需要先下载再读取。你的系统不应该让策略直接调用 xtdata，而应当把 xtdata 封装成 SourceAdapter。 xttrader 则适合封装在后续的 QmtBroker / QmtGateway 中，例如下单接口最终需要映射到证券代码、买卖方向、委托数量、报价类型、价格等字段。

1. 项目目标与边界
1.1 项目目标

项目名称建议：

FundLab
Exchange-Traded Rule-Based Fund Lab
场内规则型基金投资实验系统

第一性目标不是“做一个 ETF 策略”，而是做一个长期可扩展的实验平台：

可信数据仓库
  → 统一数据接口
    → 可复现回测
      → 内部虚拟模拟盘
        → ETF / 场内基金雷达
          → Agent 虚拟投资者
            → MiniQMT 自动执行
              → 报告与推送

你的平台要解决三个可信问题：

数据可信：
  数据来源、清洗、复权、缺失、停牌、估值可得性、分红、折溢价都可追溯。

回测可信：
  严格区分信号日、可得日、下单日、成交日，不允许未来函数。

模拟盘可信：
  每个虚拟账户有独立订单、成交、现金、持仓、估值、收益曲线和审计记录。
1.2 第一版资产范围

第一版建议只支持：

A 股场内 ETF
债券 ETF
黄金 ETF
跨境指数 ETF / QDII ETF
货币 ETF可以纳入，但第一版策略中尽量先作为现金替代品观察

暂不进入主流程：

REITs
指数 LOF
指数增强基金
主动 ETF
FOF
主动权益基金

原因很简单：第一阶段最重要的是把数据、回测、模拟盘闭环跑通。资产范围越宽，越容易让项目卡在分类、估值、净值、分红、流动性、交易规则差异上。

1.3 第一版非目标

第一版不要做：

分钟级回测
高频撮合
复杂订单类型
真实自动交易
多数据源仲裁
复杂 Agent 自主进化
Web 大屏
实时推送系统
完整归因系统
指数成分穿透分析

第一版要做：

日线数据可信落库
DataPortal 可用
5 个规则策略可回测
T 日收盘信号，T+1 日开盘成交
手续费、滑点、成交额限制
分红现金入账
折溢价风控
内部虚拟模拟账户
每日账户净值和持仓可追溯

3. 子系统职责拆分
3.1 data_system

职责：

从 xtquant / akshare / 手工表 / 其他数据源读取数据；
清洗字段；
统一 symbol；
处理交易日历；
处理停牌、缺失、复权、净值、分红、估值可得性；
落库；
提供质量校验报告；
最终只通过 DataPortal 对上层开放。

核心原则：

Source 负责“拿原始数据”
Loader 负责“按业务主题拉取”
Processor 负责“清洗标准化”
Store 负责“存储”
DataPortal 负责“按时间点可信读取”
3.2 backtest

职责：

加载历史数据；
调用策略生成目标仓位；
把目标仓位转成订单；
做风控；
按成交模型成交；
维护现金、持仓、成本、分红；
每日估值；
输出订单、成交、持仓、净值、绩效。

策略不记账，策略只返回：

{
    "510300.SH": 0.30,
    "510500.SH": 0.20,
    "518880.SH": 0.10,
    "cash": 0.40
}
3.3 sim / paper trading

职责：

维护内部虚拟账户；
每天真实推进一次；
使用当日数据更新估值；
使用策略或 Agent 生成订单意图；
经过风控；
由 PaperBroker 虚拟成交；
保存所有订单、成交、现金、持仓、收益。

它和 backtest 复用：

Order
Trade
Position
Account
Portfolio
CostModel
SlippageModel
RiskChecker
PerformanceAnalyzer

不同点是：

BacktestBroker: 历史撮合
PaperBroker: 内部模拟撮合
QmtBroker: 后续真实或 MiniQMT 模拟交易
3.4 radar

职责：

每天把原始行情、估值、分红、流动性、折溢价变成可读信号；
服务于人工观察、策略筛选、Agent 上下文、日报推送。
3.5 agent

职责：

读取 DataPortal 和自身记忆；
输出结构化决策 JSON；
不得绕过风控；
不得直接修改账户；
不得直接调 xttrader；
不得篡改历史收益；
只允许写入复盘、假设、观察笔记。
3.6 qmt execution

职责：

后续把内部订单对象映射到 xttrader；
查询 MiniQMT 资产、委托、成交、持仓；
做实盘/模拟盘状态对账；
保留独立审计。

7. 核心数据表设计

下面是逻辑表结构。实际落地时，日线和特征可以放 Parquet，但仍然应该按这些主键和约束来设计。

7.1 fund_master

用途：

核心 universe 表；
管理基金分类；
判断是否纳入研究；
避免主动基金混入；
支持未来解决幸存者偏差。
表结构
CREATE TABLE fund_master (
    symbol                  TEXT PRIMARY KEY,      -- 510300.SH
    raw_symbol              TEXT,                  -- 原始代码
    name                    TEXT NOT NULL,
    exchange                TEXT NOT NULL,          -- SH / SZ / BJ
    product_type            TEXT NOT NULL,          -- ETF / LOF / REIT / MONEY_ETF
    management_type         TEXT NOT NULL,          -- passive_index / smart_beta / active / enhanced / fof
    asset_class             TEXT NOT NULL,          -- equity / bond / commodity / money_market / cross_border / reits
    category                TEXT,                   -- broad_based / sector / theme / dividend / gold / treasury_bond
    tracking_index          TEXT,
    tracking_index_code     TEXT,
    fund_company            TEXT,
    listed_date             DATE,
    delisted_date           DATE,
    expense_ratio           REAL,
    custody_fee             REAL,
    lot_size                INTEGER DEFAULT 100,
    price_tick              REAL DEFAULT 0.001,
    is_active               INTEGER NOT NULL DEFAULT 1,
    include_in_universe     INTEGER NOT NULL DEFAULT 0,
    exclusion_reason        TEXT,
    source                  TEXT,
    source_updated_at       TIMESTAMP,
    created_at              TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at              TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_fund_master_universe
ON fund_master(include_in_universe, is_active, product_type, management_type);

CREATE INDEX idx_fund_master_asset_class
ON fund_master(asset_class, category);

CREATE INDEX idx_fund_master_tracking_index
ON fund_master(tracking_index_code);
字段约束建议
management_type:
  passive_index
  smart_beta
  passive_bond
  passive_commodity
  passive_money_market
  cross_border_index
  index_enhanced
  active
  fof
  unknown

asset_class:
  equity
  bond
  commodity
  money_market
  cross_border
  reits
  mixed
  unknown

product_type:
  ETF
  LOF
  REIT
  MONEY_ETF
  OTHER
更新逻辑
每日或每周更新：
  1. 从 xtquant 合约基础信息拉取当前可交易品种；
  2. 从补充源拉取 ETF / LOF 基础资料；
  3. symbol_normalizer 标准化为 510300.SH；
  4. 按 symbol upsert；
  5. 不删除退市品种，只设置 is_active = 0；
  6. include_in_universe 由规则和人工白名单共同决定；
  7. 主动基金、FOF、无法识别管理方式的品种默认 exclude；
  8. 每次变更写入 fund_master_audit。

建议增加审计表：

CREATE TABLE fund_master_audit (
    audit_id        TEXT PRIMARY KEY,
    symbol          TEXT NOT NULL,
    field_name      TEXT NOT NULL,
    old_value       TEXT,
    new_value       TEXT,
    reason          TEXT,
    changed_by      TEXT,
    changed_at      TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

后续为解决幸存者偏差，增加：

CREATE TABLE fund_master_snapshot (
    snapshot_date            DATE NOT NULL,
    symbol                   TEXT NOT NULL,
    name                     TEXT NOT NULL,
    exchange                 TEXT NOT NULL,
    product_type             TEXT NOT NULL,
    management_type          TEXT NOT NULL,
    asset_class              TEXT NOT NULL,
    category                 TEXT,
    tracking_index_code      TEXT,
    is_active                INTEGER NOT NULL,
    include_in_universe      INTEGER NOT NULL,
    PRIMARY KEY (snapshot_date, symbol)
);

第一版可以先没有完整历史 snapshot，但所有回测报告必须写：

当前回测 universe 基于当前可获得基金列表，存在幸存者偏差，结果可能偏乐观。
7.2 trading_calendar

用途：

统一交易日判断；
回测时间推进；
T+1 成交；
周度/月度调仓；
避免用自然日误判。
表结构
CREATE TABLE trading_calendar (
    date                    DATE PRIMARY KEY,
    exchange                TEXT NOT NULL DEFAULT 'CN',
    is_trading_day          INTEGER NOT NULL,
    previous_trading_day    DATE,
    next_trading_day        DATE,
    is_month_end            INTEGER DEFAULT 0,
    is_week_end             INTEGER DEFAULT 0,
    is_quarter_end          INTEGER DEFAULT 0,
    created_at              TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at              TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

CREATE INDEX idx_trading_calendar_trading
ON trading_calendar(is_trading_day, date);

CREATE INDEX idx_trading_calendar_month_end
ON trading_calendar(is_month_end, date);
更新逻辑
1. 优先从 xtdata.get_trading_calendar 或等价接口更新；
2. 至少维护未来 12 个月交易日；
3. 每次更新后重新计算 previous_trading_day / next_trading_day；
4. 计算 is_week_end / is_month_end；
5. 回测、模拟盘全部依赖此表，不允许自己用 pandas bdate_range 猜交易日。
7.3 fund_daily_bar

用途：

日线行情核心表；
第一版所有回测、模拟盘、特征计算都基于它。
逻辑结构
-- 实际可用 Parquet 存储，此处表示逻辑 schema
CREATE TABLE fund_daily_bar (
    date            DATE NOT NULL,
    symbol          TEXT NOT NULL,
    open            REAL,
    high            REAL,
    low             REAL,
    close           REAL,
    volume          REAL,
    amount          REAL,
    pre_close       REAL,
    adj_factor      REAL,
    suspended       INTEGER DEFAULT 0,
    limit_up        REAL,
    limit_down      REAL,
    source          TEXT,
    updated_at      TIMESTAMP,
    PRIMARY KEY (date, symbol)
);

CREATE INDEX idx_fund_daily_bar_symbol_date
ON fund_daily_bar(symbol, date);

CREATE INDEX idx_fund_daily_bar_date
ON fund_daily_bar(date);
Parquet 字段类型建议
date: date32
symbol: string
open/high/low/close/pre_close/adj_factor/limit_up/limit_down: float64
volume: float64
amount: float64
suspended: bool
source: string
updated_at: timestamp
更新逻辑
每日收盘后：
  1. 获取 universe 中所有 active symbol；
  2. 对每个 symbol 增量下载最近 N 日，N 建议 10；
  3. 用 symbol + date 去重；
  4. 检查 open/high/low/close 合法性；
  5. 检查 amount、volume 是否异常；
  6. 检查 date 是否为交易日；
  7. 如果该交易日无行情：
       - 若 suspended = true，保留停牌记录；
       - 若无法判断，写入 quality_issue；
  8. 写入 Parquet；
  9. 更新 data_update_log。
质量校验
open <= high
low <= high
close <= high
close >= low
amount >= 0
volume >= 0
pre_close 非空率
重复主键检查
缺失交易日检查
极端涨跌幅检查

7.5 fund_nav

用途：

ETF / LOF / 跨境 ETF 折溢价；
QDII / 跨境 ETF 风控；
净值与收盘价偏离分析。
表结构
CREATE TABLE fund_nav (
    date                    DATE NOT NULL,
    symbol                  TEXT NOT NULL,
    nav                     REAL,
    iopv                    REAL,
    close                   REAL,
    premium_discount        REAL,
    estimate_nav            REAL,
    available_date          DATE,
    source                  TEXT,
    updated_at              TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (date, symbol)
);

CREATE INDEX idx_fund_nav_symbol_date
ON fund_nav(symbol, date);

CREATE INDEX idx_fund_nav_available
ON fund_nav(symbol, available_date);
关键逻辑

premium_discount 计算：

premium_discount = close / nav - 1

如果是跨境 ETF：

优先使用 estimate_nav / IOPV；
如果 nav 发布滞后，则 DataPortal 必须按 available_date 读取；
回测中不能在 T 日使用 T 日之后才公布的 NAV。
更新逻辑
1. 每日更新 close；
2. nav / iopv / estimate_nav 从可用数据源拉取；
3. 对于晚公布数据，available_date 必须晚于或等于 date；
4. DataPortal 查询时只允许 available_date <= signal_date；
5. 缺失 NAV 的基金可以参与普通价格策略，但不能参与 premium_discount 风控通过。

payment_date:

默认 payment_date = ex_dividend_date

分红到账日使用简化假设。

特征计算规则

8.3 asof 语义

DataPortal 所有与估值、净值、分红、特征相关的接口都要支持：

asof

默认：

asof = date

但回测中建议显式传入：

data_portal.get_features(symbols, date=signal_date, asof=signal_date)

含义：

站在 signal_date 当天收盘后，只能看到 available_date <= signal_date 的数据。
8.4 缺失值策略

不要默默填充所有缺失。推荐分层：

价格缺失：
  - 策略读取时默认返回缺失；
  - 估值时允许用 previous_close 估值，但必须标记 stale_price = true；
  - 成交时不允许用 previous_close 成交。

估值缺失：
  - 红利低估策略应剔除；
  - 普通动量策略可以忽略估值字段。

NAV 缺失：
  - 跨境 ETF 折溢价风控无法通过；
  - 非跨境 ETF 可根据配置放行。

特征缺失：
  - 低于 warmup window 的品种不参与排序；
  - 不允许填 0 后排序。

11. 回测主流程
11.1 推荐时序

默认采用：

T 日收盘后生成信号
T+1 日开盘成交
每日收盘价估值

这能避免最常见的错误：

同一天收盘价既生成信号又作为成交价。
11.2 事件流
初始化：
  1. 加载配置
  2. 加载交易日历
  3. 初始化账户
  4. 初始化策略
  5. 初始化 Broker / CostModel / SlippageModel / RiskChecker
  6. 创建 run_id
  7. 记录 config_hash / data_version / git_commit

for date in trading_days:

  [盘前 / 开盘]
  1. 处理上一个 signal_date 生成、计划在 date 执行的订单意图
  2. 用 date 的 open 价格进行模拟成交
  3. 先卖后买
  4. 检查停牌、涨跌停、成交额限制、现金、最小交易单位
  5. 生成 Trade
  6. Accounting 更新现金与持仓

  [日内忽略，MVP 不做]

  [收盘]
  7. 使用 close 做 mark-to-market
  8. 处理分红应收 / 到账
  9. 记录 account_daily
  10. 记录 position_daily

  [收盘后]
  11. 如果 date 是调仓日：
        a. Strategy.on_rebalance(date, data_portal, context)
        b. 返回 target_weights
        c. 检查权重合法性
        d. 风控预检查
        e. 生成 OrderIntent
        f. execution_date = next_trading_day(date)
        g. 保存 pending intents
11.3 伪代码
class BacktestEngine:
    def run(self):
        trading_days = self.data_portal.get_trading_days(
            self.start_date, self.end_date
        )

        for date in trading_days:
            self.current_date = date

            # 1. 执行此前生成、今日成交的订单
            intents = self.recorder.load_order_intents(execution_date=date)
            if intents:
                orders = self.execution_planner.create_orders(
                    intents=intents,
                    account=self.account,
                    execution_date=date,
                    data_portal=self.data_portal,
                )

                orders = self.risk_checker.check_orders(
                    orders=orders,
                    account=self.account,
                    date=date,
                    data_portal=self.data_portal,
                )

                trades = self.broker.execute_orders(
                    orders=orders,
                    account=self.account,
                    date=date,
                    data_portal=self.data_portal,
                )

                self.accounting.apply_trades(self.account, trades)
                self.recorder.record_orders(orders)
                self.recorder.record_trades(trades)

            # 2. 分红处理
            dividend_events = self.accounting.process_dividends(
                account=self.account,
                date=date,
                data_portal=self.data_portal,
            )
            self.recorder.record_account_events(dividend_events)

            # 3. 收盘估值
            self.accounting.mark_to_market(
                account=self.account,
                date=date,
                data_portal=self.data_portal,
                price_field="close",
            )

            self.recorder.record_account_daily(date, self.account)
            self.recorder.record_position_daily(date, self.account.positions)

            # 4. 收盘后生成下一交易日订单意图
            if self.schedule.is_rebalance_day(date):
                context = self.build_context(date)
                target_weights = self.strategy.on_rebalance(
                    date=date,
                    data_portal=self.data_portal,
                    context=context,
                )

                target_weights = self.normalize_target_weights(target_weights)

                checked_targets = self.risk_checker.check_target_weights(
                    target_weights=target_weights,
                    account=self.account,
                    date=date,
                    data_portal=self.data_portal,
                )

                next_date = self.data_portal.next_trading_day(date)
                intents = self.execution_planner.create_order_intents(
                    account_id=self.account.account_id,
                    strategy_id=self.strategy.strategy_id,
                    signal_date=date,
                    execution_date=next_date,
                    target_weights=checked_targets,
                )

                self.recorder.record_order_intents(intents)

        self.metrics = self.performance_analyzer.analyze(self.recorder)
        self.recorder.record_metrics(self.metrics)
12. 目标仓位到订单
12.1 目标权重合法性

规则：

所有 symbol 权重 >= 0
cash 权重 >= 0
sum(symbol_weights) + cash <= 1.0001
如果未传 cash，则 cash = 1 - sum(symbol_weights)
单品种不超过 max_weight_per_symbol
不在 universe 的 symbol 拒绝
停牌品种不能买入，可以继续持有
12.2 订单生成

推荐流程：

1. 在 T 日收盘后只保存 target_weight intent。
2. T+1 日开盘时，用 open price 计算目标股数。
3. 当前持仓与目标股数差额形成订单。
4. 卖单先执行，买单后执行。
5. 买单根据现金不足情况等比例缩放。
6. 买入数量按 lot_size 向下取整。
7. 卖出数量不能超过当前持仓。
目标股数计算
target_value = account_total_asset_at_execution * target_weight
target_quantity_raw = target_value / execution_price
target_quantity = floor(target_quantity_raw / lot_size) * lot_size
差额订单
delta_quantity = target_quantity - current_quantity

delta_quantity > 0:
  buy

delta_quantity < 0:
  sell
12.3 现金权重

不要对 cash 生成订单。cash 是结果：

cash = total_asset - market_value_after_trades - fees
13. 成交模型、费用模型、滑点模型

LEAN / QuantConnect 把手续费、滑点、成交、容量等作为 reality models，这个思想很适合你；尤其 ETF 里有很多低流动性品种，默认假设“高度流动”会让回测失真。

13.2 simple_close

虽然名字叫 simple_close，但根据你的原则，建议实际使用：

信号：T close
成交：T+1 open
估值：每日 close

模型：

成交价 = T+1 open
手续费 = commission_rate * amount
滑点 = 0
无成交额限制
停牌不成交

用途：

验证回测引擎主流程。
13.3 realistic_daily

模型：

成交价 = T+1 open * slippage_adjustment
手续费 = max(amount * commission_rate, min_commission)
成交额限制 = 当日 amount * max_participation_rate
不能买入 suspended = true 的品种
不能买入 premium_abs 超限的跨境 ETF
低流动性产品增加滑点

买入：

fill_price = open * (1 + slippage_bps / 10000)

卖出：

fill_price = open * (1 - slippage_bps / 10000)

成交量限制：

max_trade_amount = daily_amount * max_participation_rate
requested_amount = abs(quantity * fill_price)

if requested_amount > max_trade_amount:
    partial fill or reject

第一版建议：

allow_partial_fill = true

并记录：

partial_fill_reason = "participation_limit"
13.4 conservative

模型：

基础滑点更高；
低流动性惩罚更高；
折溢价异常直接拒绝；
成交额限制更严格；
开盘价异常时改用更差价格。

示例：

execution:
  model: conservative

slippage:
  base_bps: 5
  low_liquidity_penalty_bps: 10
  max_participation_rate: 0.02

risk:
  max_premium_abs: 0.02

用途：

压力测试策略是否只在理想撮合下有效。

16. 模拟盘系统设计
16.1 模拟盘定位

模拟盘不是 MiniQMT 模拟账户的替代 UI，而是你的内部可审计账户系统。

MiniQMT 模拟账户：
  真实接口测试；
  少数策略验证报单链路；
  后续实盘执行通道。

内部虚拟账户：
  每个策略 / Agent 一个账户；
  可并行运行；
  可完全审计；
  不依赖 MiniQMT 账户数量；
  与回测账务模型一致。

vn.py 的本地仿真、组合管理、风险管理、事件引擎、数据库适配等思想值得参考；但第一版不建议引入完整 vn.py，因为你的日线 ETF 实验平台不需要 GUI、多网关、高频事件引擎这些复杂度。

示例结构
class XtQuantSource(MarketDataSource):
    name = "xtquant"

    def __init__(self, config):
        self.config = config
        self.connected = False

    def connect(self):
        from xtquant import xtdata
        self.xtdata = xtdata
        self.connected = True

    def download_daily_bar(self, symbols, start_date, end_date):
        for symbol in symbols:
            self.xtdata.download_history_data(
                stock_code=symbol,
                period="1d",
                start_time=start_date.replace("-", ""),
                end_time=end_date.replace("-", ""),
            )

    def get_daily_bar(self, symbols, start_date, end_date):
        return self.xtdata.get_market_data_ex(
            field_list=[],
            stock_list=list(symbols),
            period="1d",
            start_time=start_date.replace("-", ""),
            end_time=end_date.replace("-", ""),
            count=-1,
            dividend_type="none",
            fill_data=False,
        )

实际参数需要按你本机 xtquant 版本校正。关键是：

先 adapter；
后清洗；
再落库；
上层永远不直接依赖 xtdata 返回格式。

19. 如何避免未来函数

这是整个系统的生死线。

19.1 四个时间必须分开
data_date:
  数据对应的市场日期。

available_date:
  数据在系统中可被看到的日期。

signal_date:
  策略生成信号的日期。

execution_date:
  订单成交日期。

示例：

2026-05-06 close 产生信号
2026-05-07 open 成交
2026-05-07 close 估值

估值数据：

index_valuation.date = 2026-05-06
index_valuation.available_date = 2026-05-07

那么在 2026-05-06 生成信号时不能用这条估值。

19.2 DataPortal 强制 asof

所有 PIT 数据读取都必须：

available_date <= asof

包括：

index_valuation
fund_nav
fund_features_daily
fund_dividend
fund_master_snapshot
19.3 策略不能读取未来价格

策略只允许：

data_portal.get_daily_bar(
    symbols,

    end_date=signal_date,

3. payment_date 增加 cash；
4. account_event_ledger 记录 dividend_paid；
5. performance 同时支持 price_return 和 total_return。

最小实现：

如果 record_date / payment_date 缺失：
  用 ex_dividend_date 作为到账日。

报告标记：

分红到账日存在简化假设。
20.2 折溢价

跨境 ETF 必须启用：

risk:
  max_premium_abs: 0.03

买入规则：

premium_discount 缺失：
  跨境 ETF 拒绝买入。

premium_discount > 3%：
  拒绝买入。

premium_discount < -3%：
  允许，但仍需检查流动性。

卖出规则：

已有持仓允许卖出；
极端折溢价只限制新增买入。
20.3 流动性

三层限制：

准入限制：
  amount_avg_20d >= 3000 万

成交限制：
  单笔成交金额 <= 当日成交额 * 5%

滑点惩罚：
  低于成交额阈值的 ETF 增加滑点

低流动性品种不能只靠“加滑点”解决，必须有硬过滤。否则回测容易出现“流动性幻觉”。

29. 主要技术风险与规避方案
29.1 幸存者偏差

风险：

只用当前存在 ETF 回测过去，结果偏乐观。

第一版处理：

报告显式标记幸存者偏差；
fund_master 保留 listed_date / delisted_date；
不删除退市品种。

后续处理：

补历史 ETF 列表；
建立 fund_master_snapshot；
回测按 date 查询当时 universe。
29.2 未来函数

风险：

估值、净值、特征、分红公告使用了未来数据。

规避：

所有 PIT 数据必须有 available_date；
DataPortal 强制 available_date <= asof；
策略只拿 signal_date 之前数据；
执行价只给 Broker。
29.3 分红低估

风险：

高股息 ETF 如果只看价格收益，会低估总收益。

规避：

fund_dividend；
dividend_receivable；
payment_date cash 入账；
报告区分 price return 和 total return。
29.4 跨境 ETF 溢价

风险：

高溢价买入，净值回归后亏损；
回测如果不用折溢价会过度乐观。

规避：

fund_nav；
premium_discount；
max_premium_abs；
缺失折溢价的跨境 ETF 禁止新增买入。
29.5 流动性幻觉

风险：

低成交额 ETF 回测收益很好，但实际无法成交。

规避：

amount_avg_20d 准入；
max_participation_rate；
低流动性滑点惩罚；
部分成交或拒单；
报告显示容量限制影响。
29.6 xtquant 版本差异

风险：

不同券商 MiniQMT / xtquant 字段、行为、连接方式不同。

规避：

xtquant_source 隔离；
raw 数据落盘；
字段映射配置化；
集成测试覆盖本机环境；
核心回测不依赖 xtquant 在线。
29.7 数据源不稳定

风险：

NAV、估值、分红源缺失或更新延迟。

规避：

source 字段；
available_date；
data_update_log；
quality_issue；
缺失时策略降级或剔除。
29.8 过早接 Agent

风险：

Agent 看似智能，但账户、收益、风控不可信。

规避：

Agent 后置；
先跑规则策略；
Agent 只能输出 JSON；
所有动作经过 RiskEngine 和 Broker；
Agent 不能改账本。
30. 最推荐的 MVP 路线

最务实的 8 周内路线可以是：

第 1 周：
  项目骨架、SQLite、配置、日志、交易日历、fund_master。

第 2 周：
  xtquant_source、daily_bar_loader、Parquet、DataPortal.get_daily_bar。

第 3 周：
  NAV、分红、估值、feature 计算、quality checker。

第 4 周：
  Account / Order / Trade / Position / Cost / Slippage / BacktestBroker。

第 5 周：
  BacktestEngine、Recorder、Metrics、等权宽基、红利低估。

第 6 周：
  动量轮动、股债商配置、估值动量双因子、风控完善。

第 7 周：
  分红入账、折溢价限制、流动性限制、未来函数测试、回测报告。

第 8 周：
  PaperBroker、VirtualAccount、每日模拟盘流程、模拟盘报告。

最终 MVP 验收口径：

1. 可以稳定更新 ETF 日线数据；
2. 可以查询 point-in-time universe；
3. 可以计算每日特征；
4. 可以跑 5 个策略；
5. 回测严格 T 日信号、T+1 日成交；
6. 分红进入现金；
7. 跨境 ETF 高溢价会被限制；
8. 低流动性不能无限成交；
9. 每次回测有 run_id、config_hash、data_version；
10. 内部模拟盘每天有订单、成交、持仓、净值；
11. 所有结果可复现、可追溯、可审计。

这个方案最关键的取舍是：**先不要追求策略复杂度，也不要急着接 Agent 或实盘自动执行；先把数据、账本、时点、成交、风控和结果记录做硬。**只要这三层可信，后面的 ETF 雷达、Agent 排名、日报推送、MiniQMT 自动执行都只是自然扩展。
